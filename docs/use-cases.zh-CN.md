# 适用场景与限制

[English](use-cases.en.md) · [使用指南](usage.zh-CN.md)

## 适合做什么

- **固定机位训练、半场比赛**：篮筐位置稳定，球颜色和尺寸可辨，用 CPU 先找候选，再查看短时序画面。
- **长视频的人工剪辑导航**：交付原视频时间码和 SRT 辅助轨，减少剪辑师来回拖动时间线找球的工作。
- **无独立 GPU 的电脑**：基础筛选采用 OpenCV/NumPy；时间表输出采用 Python 标准库，无需 CUDA。
- **NAS 素材**：用已挂载的文件路径读取，不需要上传云端或将整个视频转码一遍。
- **已有复核数据**：直接复用事件 JSON，生成表格或重新导出不同标记长度的 SRT。

## 需要额外处理

| 条件 | 建议 |
| --- | --- |
| 摄像机平移、变焦或换机位 | 先分出机位稳定的区段，重新确认 ROI；内置检测 CLI 本身不自动分段 |
| 多个篮筐 | 按篮筐/区段分别检查并合并去重；脚本每次只接收一个 ROI |
| 球很小、严重模糊、被人或篮板挡住 | 增加视觉复核；无法判断时保留待复核，不自动计入进球 |
| HDR、特殊编码或旋转显示异常 | 先验证解码与显示；保持原始时间轴，必要时使用兼容编辑器 |
| 已剪切或变速的剪映时间线 | 使用原视频零点时间线，或先建立明确的时间换算 |

## 不提供的保证

- 没有附带训练模型权重，也没有多人球轨迹身份追踪的生产级实现。
- 不保证找全全部进球；稀疏截图只能导航，不能证明没有漏检。
- 篮筐附近出现球、擦筐或篮网晃动，都不能单独证明进球。
- 检测置信度是启发式分数，不是经过校准的进球概率。
- 没有本版全场 precision/recall 基准或固定处理速度承诺。
- SRT 是辅助字幕轨，不是剪映原生标记或完整草稿工程。

## 速度与准确性

本版减少的是视频预览转码、逐段导出和完整投篮动作检查。解码全片、NAS 读取和复核候选仍有成本。默认保留逐帧候选检测，避免靠大幅跳帧换速度而错过短暂入筐。已有事件优先复用，仅放大检查模糊候选。

## 数据与授权

处理脚本在本机运行，不要求云端服务。请自行确保对输入视频有处理和分享权限。仓库示例全部为合成数据；不要提交真实素材、NAS 地址、模型密钥或个人配置。
